Pre-rubric: written before docs/self-improvement/rubric.md existed, with criteria and weights chosen by the grader after the evidence was in. Its 7.4 is not comparable with rubric scores.

The plugin being rated is five-whys, in the repository at /Users/joshua/Developer/Plugins/ClaudeCodeCLI/FiveWhys on branch improve/v0.3.0. Those changes are not released: the manifest still says 0.2.0, and the RedJay marketplace still serves 0.2.0. The plugin generates a complete 5x5x5x5x5 Five Whys tree (3,905 reasons) with one root agent and 25 branch agents dispatched in waves of 5. A stdlib Python script (scripts/fivewhys.py, 842 lines, plus scripts/hygiene.py, 140 lines) validates every fragment and assembles one JSON tree plus index.md and hygiene.json. Analysis is left to the user by requirement.

The unreleased changes came from round 2 (docs/self-improvement/round-2): all 3,905 reasons of the v0.2.0 full run on its 8/10 rating were classified against a 22-improvement catalog by one session without subagents. Changes: a parse subcommand for /five-whys arguments; init returns confirm for runs of more than 5 agents; waves default to 5, and later waves see finished branches' first-level reasons; stemmed hygiene with cross-branch leads; check compares branch fragments with the root's reasons; run.json records version, options and estimate; index.md lists byte-sized Read windows; the estimate is a range; the --root-model and --branch-model options were removed; a replay test and a labeled paraphrase-pair fixture; a thin-problem eval case; release gates by change kind in RELEASING.md; CHANGELOG.md; docs/self-improvement/usage.py for token measurement.

Evidence behind the 7.4/10 rating (weighted rubric, self-graded by the session that wrote the code):
1. Requirement fidelity 9/10 (weight 15%): the v0.2.0 full run made 3,905/3,905 reasons, and a model-invoked smoke run of the checkout made 39/39 without interpreting them. But no full run of the v0.3.0 code has happened.
2. Orchestration reliability 8/10 (15%): parse and confirm now live in code, headless model-invoked runs followed the skill in three scenarios (smoke, thin problem, full-size confirmation), and resume survived a machine restart. But each scenario ran once, and branch agents repaired fragments with sed rather than Edit.
3. Reason quality 6.5/10 (15%): a 20-reason sample of the smoke tree read as concrete, with 11 stated assumptions. But quality has never been measured systematically: no rubric, no second model, no outside reader, and the non-software eval never ran.
4. Hygiene 7/10 (10%): on labeled pairs from a real tree, stemming and cross-branch leads catch 7 of 16 convergent pairs where v0.2.0 caught 0. But detection is still lexical: it misses 9 of 16 and lists 2 of 8 distinct pairs as leads.
5. Cost transparency 6.5/10 (10%): the estimate is a range of 0.60M-1.62M agent tokens from two measured runs, and the setting driving the gap is known (session context and evidence reading). But the range is wide, each end comes from one run on one model, and wall clock has never been measured.
6. Testing 7.5/10 (10%): 61 unit tests pass in CI on Python 3.9 and 3.12, with the replay test, labeled pairs and docs-consistency tests. But the eval has never run, because claude plugin eval refuses Bash-granting cases on this machine (symlinks in ~/.docker/cli-plugins), and the live checks were single samples.
7. Release process and docs 7.5/10 (10%): gates are defined by change kind, each gate's evidence is recorded in CHANGELOG.md, and the README states its limitations. But 0.3.0 is not released, and the same session wrote and passed the gates.
8. Maintainability 7/10 (5%): options dropped from 14 to 10 and hygiene was split into its own module. But fivewhys.py grew from 725 to 842 lines, and there are more documents to keep consistent.
9. Self-improvement process 7/10 (5%): every reason was accounted for, a sampled audit found and fixed 5 wrong codes (about 8%), and a review outside the tree found two real bugs. But one model family wrote the tree, the ledger and the audit, and 2,735 reasons inherit their parent's disposition line.
10. Readiness for other users 6/10 (5%): local-only, no dependencies, resumable. But unreleased, no outside users, and the eval is blocked.

What the grading says would reach 9-10: run the eval once the ~/.docker symlink issue is resolved, then release 0.3.0; a timed full run of v0.3.0 in waves of 5 in a clean directory; a small scored quality study with a second model or a human; a full run on a non-software problem; one outside user's run.
