## Notes

- **Baseline correction.** The 60% figure quoted before this goal counted folder
  paths such as `scripts/`. The measurement script uses the plugin's own file-path
  pattern, under which the before-run had 47.5%.
- **Why G1c isn't met.** How-answers now describe actions in order, but a
  mechanism names the things it acts on, which are what the what-answers name.
  Word overlap counts those shared nouns. Pushing it lower would make
  how-answers vaguer, so the guidance was not tuned toward this number. A
  better measure would ignore the nouns the input itself supplies.
- **Answer length by model.** On opus, how-answers averaged 17.0 words before the
  guidance change and 17.2 after, with no over-length answers. In G3, sonnet's
  level-1 how-answers averaged 21.3 words and haiku's deeper ones 24–25 (max 34),
  leaving 13 over-length answers; haiku's what-answers averaged 13–15 words.
- **Where evidence came from.** The rerun's answers about plugin-eval were
  mostly accurate because an agent read `.remember/`, the git-ignored folder
  where the session's memory notes live. Agents stayed inside the project
  folder, but read notes that aren't part of the project. After the
  private-folder rule (07f6439), the same inputs' agents read `.remember/` or
  `.env` 0 times, against 4 in pass 1.
- **Pass 2 how-answers** lead with an action ("Scanning ~/.docker at eval start,
  claude plugin eval finds symbolic links and refuses each case granting
  Bash."), yet what-how overlap barely moved, which supports the diagnosis
  above. Why-what overlap rose from 0.044 to 0.051. Cross-branch leads fell
  from 8 to 1.
- **References.** Reassembling the before-run flagged one path,
  `aggregate-result.json` in `6.how.5`, which exists only inside a git-ignored
  results folder. The rerun flagged none.
